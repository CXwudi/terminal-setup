# Zsh Configuration

These examples target Debian/WSL with Oh My Zsh and Powerlevel10k. The [base setup](../setup-guide/Zsh%20-%20setup.md) installs the shell and plugins; the [further setup](../setup-guide/Zsh%20-%20Further%20Setup.md) installs mise and its tools.

## Startup responsibilities

| File | Loaded for | Contents |
| --- | --- | --- |
| [.zshenv](./.zshenv) | Every normal Zsh invocation | Private exports, base PATH, default Java, editor, and optional CUDA paths |
| [.zprofile](./.zprofile) | Login shells | Reuse or start an SSH agent |
| [zshrc.custom.zsh](./zshrc.custom.zsh) | Merge into interactive `~/.zshrc` | Theme, plugins, aliases, and mise activation |

`.zprofile` runs for every login shell, including `zsh -lc`. `.zshrc` runs only for interactive shells. [Zsh startup rules](https://zsh.sourceforge.io/Doc/Release/Files.html#Startup_002fShutdown-Files)

## Install the examples

From the repository root, copy the shared environment and login file:

```bash
cp zsh-setting/.zshenv "$HOME/.zshenv"
cp zsh-setting/.zprofile "$HOME/.zprofile"
```

Then merge the two sections of `zshrc.custom.zsh` into the `~/.zshrc` generated by Oh My Zsh:

1. Put the theme and plugin declarations before `source "$ZSH/oh-my-zsh.sh"`.
2. Put aliases, the Powerlevel10k configuration load, and mise activation after that source line.
3. Keep the generated Powerlevel10k instant-prompt block near the top, and retain one load of `~/.p10k.zsh` and one mise activation.

The fragment labels the insertion points; it is a reference for editing the generated file. It is not a replacement for the entire `.zshrc`.

Set up `~/.env_var` using the [environment-variable guide](../env_var/). Open a new Zsh terminal after installation.

## Environment behavior

The PATH array uses `typeset -U` to avoid duplicates in nested shells. It includes personal bin directories and mise shims without running mise during every non-interactive startup.

`JAVA_HOME` preserves a value selected by the parent process; otherwise it points to mise's `installs/java/global` link. After the global Java declaration is installed, mise maintains that link when rebuilding its runtime links. [Stable global paths](https://mise.jdx.dev/ide-integration.html#a-fixed-path-to-the-global-version)

Interactive mise activation supplies the current project's environment. For scripts that need a project's complete Java environment, use:

```zsh
mise exec -- ./gradlew build
```

The `PNPM_HOME` setting locates pnpm data and preserves an inherited value or one loaded from `.env_var`. Bun uses its own default data directories; set directory overrides only when choosing a custom location. mise manages both executables.

The PATH array includes `"$PNPM_HOME/bin"` and `"$HOME/.bun/bin"` for globally installed commands, after mise shims. Bun's directory override variables remain unset. Update the Bun PATH entry if its default global bin location changes or you choose a custom one. [Bun directory settings](https://bun.com/docs/runtime/bunfig)

The optional CUDA block only adds existing `/usr/local/cuda/bin` and `/usr/local/cuda/lib64` directories. Install and configure the CUDA toolkit separately if a workload needs it.

The SSH agent logic accepts an empty but reachable agent, reuses a working inherited or cached agent, and creates the agent environment file with mode `600`. It does not load SSH keys automatically.
